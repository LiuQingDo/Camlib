# 媒体编辑功能实施方案（视频剪辑 + 图片编辑）

## Context

Camlib 是相机媒体库应用（Tauri 2 + Rust + Vanilla TS + SQLite）。当前媒体只能浏览/收藏/打标/删除，缺少对照片和视频的后期处理能力。本次为媒体增加：
- **图片编辑**：旋转 90°（左/右）、水平/垂直翻转、交互式拖拽裁剪、亮度/对比度/饱和度调节（滑杆实时预览）
- **视频剪辑**：片段裁剪（掐头去尾）。默认**快速模式**（ffmpeg 流复制，无损、秒级）；可选**精确模式**（重编码，切点精确，带进度、可取消）
- **保存方式**：遵循「原片只读」原则（docs/architecture.md），结果**另存为新文件**写入原文件旁（`{原名}_edited.{ext}`，重名自动递增 `_edited_2`），随后自动触发增量扫描入库成为新条目，原图不动

不改动数据库 schema（新文件由扫描器自然入库，分组键 `{date}:{stem}` 下 `_edited` 后缀不会与原文件或实况配对冲突，已验证 scanner.rs:390/476）。V1 不做：实况照片编辑、视频截帧存图、替换原图（可作后续扩展）。

## 后端（Rust）

### 1. 新模块 `src-tauri/src/editing.rs`（参照 library_merge.rs 的结构）

**图片编辑** `edit_image(details, root, params) -> EditResultDto`（在 `spawn_blocking` 中执行，复用 `media::IMAGE_DECODE_LOCK` 串行化解码）：
- 解码：jpg/png/webp 用 `image` crate；heic/heif 用 ffmpeg 兜底解码（`-i in -frames:v 1` 转临时 PNG 再加载）；其余格式报「暂不支持编辑」
- 管线：`read_exif_orientation` + `apply_orientation`（media.rs:830-857，改为 `pub(crate)`）→ 裁剪（前端传 0..1 相对坐标 `{x,y,w,h}`）→ 旋转/翻转 → 亮度/对比度（`imageops::colorops::brightness_in_place/contrast_in_place`）→ 饱和度（向灰度插值，自实现）→ 编码（PNG 源存 PNG，其余/HEIC 存 JPEG q≈92）
- 输出命名：同目录 `{stem}_edited{ext}`，重名递增；用 `TempGuard` 模式（backup.rs:1345，改 `pub(crate)`）保证失败不留残片

**视频剪辑**（job 模式，完整照抄 library_merge 范式）：
- `EditJobManagerState`（start/cancel/finish，AtomicBool 取消）+ `editing::spawn(app, manager, scan_manager, database_path, ...)` 后台线程 + `emit("edit-progress", ...)` 进度事件（DTO: jobId/kind/phase/state/percent/error + 完成时带结果）
- ffmpeg 调用复用 `resolve_ffmpeg`（media.rs:597）与 `merge_and_verify` 的样板（backup.rs:1126：`-nostdin -hide_banner -loglevel error`、临时输出、日志文件、cancel kill、成功才提交）；`ffmpeg_path_string`（backup.rs:1113）改 `pub(crate)` 复用
- 快速模式：`-ss {in} -i src -t {dur} -map 0 -c copy -avoid_negative_ts make_zero`，输出保持原扩展名
- 精确模式：重编码（libx264/aac，crf 18）+ `-progress pipe:1` 解析 `out_time_ms` 上报百分比；若编码器缺失则报错给用户
- 成功后触发增量扫描（照抄 library_merge.rs:186-202：`scan_manager.start()` + `scanner::spawn_scan(...)`）

### 2. `src-tauri/src/lib.rs` 接线
- `mod editing;` + 三个命令（参照 media_thumbnail lib.rs:771 与 library_merge_start lib.rs:1157 的写法）：
  - `media_edit_image(media_item_id, crop, rotate90, flip_h, flip_v, brightness, contrast, saturation)` —— 同步 `spawn_blocking`，内部成功后用 `State<ScanManagerState>` 触发扫描
  - `media_trim_video(media_item_id, in_ms, out_ms, precise)` —— 返回 `{jobId}`，校验 0 ≤ in < out
  - `media_edit_cancel(job_id)`
- `app.manage(editing::EditJobManagerState::new())`（lib.rs:1235 处）+ 三个命令加入 `generate_handler![...]`（lib.rs:1252）
- 路径解析复用 `resolve_media_path`（media.rs:769），通过 `get_media_item_details` 取 `single`/`photo`/`video` 角色文件的 relative_path

### 3. 测试（editing.rs 内嵌 `#[cfg(test)]`，仿 library_merge.rs:738 风格）
- 图片管线：程序生成测试图 → 裁剪+旋转+调参 → 断言输出尺寸/像素值
- 输出命名：重名递增逻辑
- 剪辑参数构造/校验的纯函数测试

## 前端（TypeScript）

### 4. `src/api/media.ts`
- DTO：`EditImageParams`、`EditResultDto { fileName, relativePath, sizeBytes, width, height }`、`EditProgressDto { jobId, phase, state, percent, error, result? }`
- 封装：`editImage(...)`、`startVideoTrim(...)`、`cancelEditJob(jobId)`、`onEditProgress(cb)`（listen `edit-progress`，仿 onLibraryMergeProgress media.ts:458）

### 5. `src/main.ts`（沿用「state 字段 + render 模板 + bind 事件」模式）
- `AppState` 增加 `editorOpen/editorItem/editorKind/editorSourceUrl/editorOps/{image 参数}/editorVideo/{inMs,outMs,durationMs,precise}/editorBusy/editorJobId/editorProgress/editorError` 等字段
- **入口**：`renderPreview`（main.ts:2198 `.modal-actions`）加「编辑」按钮；photo/video 显示（live V1 隐藏）；点击时经 `getMediaPreview` 拿 camlib:// 原图/原视频 URL，打开编辑器模态（叠加在预览之上，Esc/关闭返回预览）
- **图片编辑器**：舞台 `<img>`（浏览器自动应用 EXIF 方向，与后端 `apply_orientation` 坐标一致）+ 裁剪浮层（8 拖拽手柄 + 整体拖动，相对坐标换算）；工具条：左旋/右旋/水平翻转/垂直翻转/重置裁剪；亮度/对比度/饱和度滑杆用 CSS `filter` 即时预览；小尺寸输出预览 canvas 实时呈现 裁剪→旋转→翻转→调参 的最终结果
- **视频剪辑器**：`<video>` 播放器 + 自绘时间轴（入点/出点拖拽手柄、区间外阴影、时间标签）；「设为入点/设为出点」按钮、选区循环播放；快速/精确模式单选（注明「无损快速 / 精确较慢」）；开始后显示进度条 + 取消（edit-progress 事件驱动，仿 libraryMergeProgress 处理 main.ts:4345）
- **完成处理**：成功后 `showTransientNotice`（如「已保存为 xxx_edited.jpg，正在入库」）、关闭编辑器、`refreshMedia()`（main.ts:3449）；扫描完成事件到达后再刷一次确保新条目出现
- 复用现有组件类：`.modal-backdrop`/`.outline-button`/`.progress-track` 等；新样式（`.editor-*`、`.crop-box`、`.trim-timeline`）追加到 `src/styles.css`，沿用液态玻璃风格变量

### 6. `src/api/errors.ts`
不新增错误码，复用现有（InvalidArgument/IoError/MediaMissing/Cancelled 等）；若实现中新增枚举值则在此补中文文案

### 7. 文档
`docs/development-notes.md` 命令契约表补三个命令；`docs/architecture.md` 补一段编辑功能设计（原片只读、产物入库、可取消）

## 验证

1. `cd src-tauri && cargo fmt && cargo test && cargo check`
2. `pnpm build`（tsc 类型检查）
3. `pnpm tauri dev` 手工端到端：
   - 预览照片 → 编辑 → 旋转+裁剪+调亮度 → 保存 → 原文件未变、网格出现 `xxx_edited.jpg` 新条目且缩略图/预览正常
   - 预览视频 → 剪辑 → 设入点/出点 → 快速保存 → 新条目时长正确、内容为所选区间
   - 精确模式显示进度且「取消」生效；HEIC 照片能走 ffmpeg 兜底解码
   - 中文提示与错误路径（库离线时点编辑 → 报「媒体库不可用」）
