## 1. 目标

备份是这套产品最"值钱"的能力（源盘只读、大小校验后原子提交、深度校验可选、分段合并），但呈现方式把它埋了。本步做**降噪**，不做功能增删：

| 步骤         | 现在                                             | 改成                                                                                                                        |
| ------------ | ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| 第 1 步 选择 | 6 个控件 + 两段长说明                            | 只露「源相机盘 / 目标媒体库」；其余 4 项进「高级选项」折叠（默认收起），收起时用一行小字说明当前生效值                      |
| 第 2 步 确认 | 9 条统计 + 多段技术备注                          | 3 个数字（将复制 / 需要 / 剩余）+ 一行冲突结论；其余进「查看明细」                                                          |
| 第 3 步 执行 | 步骤指示由数据反推，取消后仍停在 3；不能回上一步 | 显式状态机：`idle → selected → previewed → running → done/failed`；每步可「返回上一步」（执行中除外）；执行中可「后台继续」 |
| 无盘         | 一行灰字「未检测到包含 DCIM 的可移动盘…」        | 三步排查 + 「刷新」按钮                                                                                                     |

另外把设置里的「整理历史分段」（`views/settings.ts:152-212`，约 60 行 UI + 完整状态机）迁到导入抽屉的第二个标签页「整理分段」。设置里只留一句指向。

## 4. 实现要点

1. **默认值不要藏起来。** 高级选项收起时必须显示当前生效值（`跳过同名 · 合并分段 · 不深度校验`），否则用户不知道自己在用什么策略——「藏起来」和「看不见」是两件事。
2. **第 2 步只回答三个问题**：拷多少 / 够不够 / 会不会覆盖。其余都是"想深究的人才会看"，放明细。
3. **状态机要真的落地。** 当前步骤条是从数据反推的，取消后仍显示"3.执行"就是反推的破绽。加显式字段后：「返回上一步」可用、取消回到合适步骤、完成后停在「完成」并可「再导入一次」。
4. **分段整理迁移不要重写逻辑。** `libraryMergePreview / libraryMergeSelected / libraryMergeProgress` 这套状态与命令都成熟，只换容器。迁移后必须确认：生成预览、勾选、合并、回收原分段、进度、取消 6 条路径都在新容器里可用。
5. **抽屉内 tab 的状态保留**：切到「整理分段」再切回「从相机导入」，已选源盘/目标与预览不应丢失（状态在 `state` 里，天然保留）。
6. **无盘排查不要写成文档。** 三行短句 + 一个刷新按钮，每行不超过 20 字。
7. **文案**：技术细节进折叠；主文案只保留结论。这是 `14.2` 的第一处落地样板，后续其他面板照此办理。

## 7. 风险与回滚

| 风险                            | 表现                       | 处理                                                                              |
| ------------------------------- | -------------------------- | --------------------------------------------------------------------------------- |
| 高级选项藏太深                  | 用户找不到"覆盖/重命名"    | summary 上直接显示当前策略，点一下即可展开；首次打开抽屉时 summary 有一次高亮脉冲 |
| 明细折叠后看不到冲突详情        | 用户直接开始备份才发现覆盖 | 有冲突时冲突结论那行用 warning 色，并在按钮上方保留一句                           |
| 分段整理迁移漏路径              | 合并按钮无响应 / 进度不动  | 迁移后按 6 条路径逐条实测；绑定用 `app.querySelector`，不依赖设置容器             |
| 步骤状态机与现有 patch 逻辑冲突 | 抽屉重开后回到错误步骤     | `backupStep` 与 `backupProgress.state` 单向同步，只在开始/取消/完成三处写         |
| 回滚                            | 中                         | 拆两个 commit：① 表单降噪 + 状态机；② 分段整理迁移                                |
