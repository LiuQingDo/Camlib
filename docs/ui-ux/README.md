# Camlib UI/UX 修复路线

> 输入：[`diagnosis.md`](diagnosis.md)（14 个维度、约 60 条问题，编号 1.1–14.4）
> 输出：`steps/` 下 14 份**可独立开一个会话做完**的任务书，每份自带完整提示词
> 适用版本：v0.6.0（Tauri 2 + Vite + 原生 TS + Rust + SQLite）

---

## 0. 怎么用这份路线

1. **一步一会话。** 新开对话，把该步第 6 节「自包含提示词」整段贴进去，不要额外补充上下文——提示词已包含项目路径、现状证据、改动边界与验收标准。
2. **按顺序做，别跳步。** 顺序不是审美排序，是依赖排序：`01` 建的 toast/notice/task 基础被 `03 / 05 / 08 / 10` 复用；`06` 依赖 `02` 的筛选数据模型；`10` 依赖 `03` 的面板化结果。
3. **每步结束必须三绿**：`pnpm test`、`pnpm lint`、`pnpm build`（涉及 Rust 时加 `cargo test`、`cargo clippy`）。再逐条勾第 5 节验收项。
4. **回填进度。** 做完把下表状态改成 ✅，commit message 带上步骤号，例如 `fix(ui): 01 反馈三通道`。
5. **发现前置不足就停。** 如果某步的「现状（已核实）」与实际代码不符（行号漂移不算），先只做定位、不硬改，回到本文件补一条备注再继续。

## 3. 全局约束（每步提示词里都重复了一遍，此处是人看的版本）

| 类别 | 约束                                                                                                |
| ---- | --------------------------------------------------------------------------------------------------- |
| 后端 | 除 `04`（搜索 SQL）与 `13`（设置读取）外不改 Rust；不改错误契约 `{code,message,retryable,details}`  |
| 性能 | 不碰 `render/virtual.ts`、卡片节点池、缩略图优先级队列；不退回「全量 innerHTML 重建」               |
| 渲染 | 沿用现有 `data-region` + `patch*()` 增量更新机制（`src/render/paint.ts`、`src/app/orchestrate.ts`） |
| 类型 | TS `strict`，禁止 `any`，禁止 `@ts-ignore`                                                          |
| 依赖 | 不新增运行时依赖（图标用自绘 SVG，不用 icon font / lucide）                                         |
| 样式 | 增量改 `styles.css`，不整体重写；新颜色一律走 `:root` 变量                                          |
| 文案 | 中文，主文案人话、技术细节进「详情」折叠                                                            |
| 交付 | 先列改动清单（文件 + 函数），再改代码，最后报三绿结果与手动验证步骤                                 |

## 4. 不做的事（明确排除）

- 不引入 React/Vue，不换渲染范式。
- 不做移动端适配，目标仍是 Windows 桌面 800×600 起的窗口。
- 不做云同步、账号体系、多语言。
- 不为了「好看」重做视觉；`diagnosis.md` 第五节列了 5 件值得保留的事，改任何一处前先读一遍。
