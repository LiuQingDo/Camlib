# Camlib UI / UX 全面诊断（基线）

> 诊断对象：`camlib` v0.6.0（Tauri 2 + Vanilla TS）
> 文档定位：**问题基线**，不做修改。修复计划见 [`README.md`](README.md)，按 [`steps/`](steps/) 逐步执行；修完一项在该条行末标 `✅ 已修（步骤 NN）`，便于下一轮对比是否回退。
> 视角：资深产品顾问，以「用户完成一次真实任务（插卡 → 备份 → 浏览 → 挑图 → 交付）」为主线审视界面与交互
> 证据：均标注代码位置，便于逐条核对
> 优先级：P0 = 阻断主任务 / 造成误操作 / 功能不可达；P1 = 显著摩擦，用户会绕路或重复操作；P2 = 打磨，影响品质感

## 一、总体结论

**这套产品的「工程完成度」明显高于「产品完成度」。**

后端安全边界（源盘只读、大小校验后原子提交、删除进回收站、断盘禁写）、渲染性能（虚拟滚动 + 卡片节点池 + 缩略图优先级队列 + 换图不重建外壳）都做到了超出同类个人项目的水平。但界面层有一个共同的结构性问题：

> **所有能力都被"平铺"到了同一个滚动面上。**

备份、扫描进度、删除结果、AI 统计、日期树、筛选、批量工具、任务横幅，全部挤进「侧栏 + 一个内容流」。结果是：主任务（看图）的容器被反复侵占；次要任务的反馈被挤出视口；用户每次操作后要靠猜来确认"到底成没成"。

三个最贵的结构性问题：

1. **备份是一个 3 步、10+ 控件的工作流，却被塞进浏览页的状态区**（`src/render/toolbar.ts:376` → `src/views/backup.ts:204`）。打开它，整个图库被推到屏幕外。
2. **反馈系统只有一个"横幅槽位"，且横幅随内容滚动**（`src/app/ui.ts:25`、`src/render/toolbar.ts:315`）。用户滚到网格中部批量收藏，成功提示出现在屏幕外 2000px 处。
3. **筛选能力是"互斥的"，但界面没说**（`src/app/bindings/toolbar.ts:51`）。"只看收藏的视频"这个最自然的组合查询，当前做不到。

## 二、五个系统性问题

### S1. 一个滚动面承载了所有任务

侧栏底部、顶栏下方、筛选条、网格，四块区域同时被导航、筛选、任务进度、结果反馈、备份表单复用。判断依据：`.sticky-controls` 里出现了 `max-height:132px; overflow:auto` 的内层滚动（`src/styles.css` `.advanced-filters`），以及标签弹层必须挂到 `.sticky-controls` 才能不被裁切（`src/render/toolbar.ts:207-224`）。**需要给祖先元素做特殊处理，通常说明布局本身已经在和 CSS 打架。**

**改造方向**：确立三区职责 —— 侧栏只做导航、内容区只做浏览、任务与反馈走"顶栏胶囊 + 独立浮层"。备份、AI 批量处理、合并这类多步任务，一律不进内容流。

### S2. 反馈通道单一且位置错误

`renderStatusBannerBase()` 是一个 if-else 链，语义搜索 > 扫描 > 断盘 > 路径无效 > error > 最近任务 > ffmpeg 提示，**同一时刻只能出现一条**（`src/render/toolbar.ts:315-357`）。所以「扫描中」会盖住「索引损坏」，「ffmpeg 提示」会盖住「上次备份失败」。同时 toast 被插在 `.sticky-controls` 之后（`src/app/ui.ts:25`），随文档流上移。

**改造方向**：三个独立通道 —— ① 必须处理的错误（顶部固定，不自动消失）；② 任务进度（顶栏胶囊，可展开、可后台）；③ 操作结果（fixed 定位的 toast 栈，2–3 条排队）。三者互不抢占。

### S3. 筛选区是"三个系统的叠加"

主行是 Tab 式（类型 + 收藏 + 连拍），折叠层是面板式（AI 搜索、标签 chip 行、原生日期双输入、评分下拉、清除），还叠了一个浮层（更多标签）。三种交互范式挤在 132px 高、sticky 吸顶的容器里。

**改造方向**：主行只留 `类型 | 收藏 | 筛选(n) | 已选条件 chips`；其余全部进一个独立筛选面板（左侧抽屉或右侧浮层），面板内不再滚动嵌套。

### S4. 能力平铺，缺少"任务"这一层抽象

扫描、备份、缩略图重建、AI 打标、视频合并、分段整理 —— 六个异步任务，六套进度 UI，六条取消路径，但用户心里只有一个概念："后台在忙什么"。当前它们分散在侧栏、横幅、设置面板、对话框底部。

**改造方向**：引入统一 Task 模型（id / 标题 / 进度 / 可取消 / 完成后的动作），UI 上收敛为一个可展开的任务胶囊。这一步做完，S1 和 S2 一半的问题自动消失。

### S5. 视觉语言过度，且 token 没有贯穿

`backdrop-filter` 出现在侧栏（26px）、吸顶栏（22px）、搜索框（18px）、遮罩（18–22px）、预览面板（28px），外加 `body::before/after` 两个 44vw 的模糊圆斑。同时深色主题需要 472 条 `[data-theme="dark"]` 覆盖规则来追平 —— 这个数字本身就是"浅色规则里硬编码了颜色"的证据（`.filter-chip { color:#555 }`、`.day-heading h2 { color:#333 }` 等）。

**改造方向**：内容区（网格、预览舞台）去玻璃，用实色中性底，把"看图"这件事的色感还给照片；颜色 100% 走 token，用 `color-no-hex` 之类的 lint 挡住裸色值。

## 四、优先级路线图

### P0（先做，约 3–4 天，改动小、收益最大）

1. **反馈三通道**：错误条（固定）/ 任务胶囊 / toast（`fixed`，可排队，带 Undo）。
   → 一举解决 5.2、10.1、10.2、10.3、10.5。
2. **筛选可叠加 + 高亮如实**：去掉 `setKindFilter` 的副作用，chip 高亮严格等于查询条件。
   → 解决 4.1（界面撒谎是产品级 bug）。
3. **备份出主区**：改为独立对话框/抽屉，进度进胶囊，完成后回图库并给"查看新增"。
   → 解决 1.1、1.2、8.4，同时让 S1 的解耦有第一个样板。
4. **搜索实时化 + 删除键位安全**：250ms 防抖；确认框 `Enter` 不再等于执行删除。
   → 解决 3.1、5.5、13.6。

### P1（一个迭代，约 2 周）

- 筛选区改造为独立面板（4.2 / 4.3 / 4.5）
- 侧栏导航重构 + 回收站入口（1.5 / 1.6 / 1.7）
- 批量工具栏收敛 + 键盘选择模型（5.1 / 5.4）
- 预览器工具合并、信息面板默认展开、滚轮语义（6.1 / 6.2 / 6.3 / 6.4）
- 图标 SVG 化 + 字阶/字重/对比度收敛（11.3 / 11.4 / 11.5）
- 深色 token 治理（12.1）、容器查询三档（12.3）
- 弹窗焦点管理 + roving tabindex（13.1 / 13.2）
- 备份默认项收敛 + 空态排查引导（8.1 / 8.2 / 8.5）
- AI 向导化（9.4）

### P2（持续打磨）

## 五、值得保留的东西（不要为了改而改）

1. **渲染性能架构**：虚拟滚动 + 卡片节点池（`render/grid.ts:157-230`）+ 缩略图优先级队列 + 换图不重建外壳（`orchestrate.ts` 注释里的取舍很清楚）。这是竞品少有的水准。
2. **错误契约**：`{ code, message, retryable, details }` + 前端 `toUserMessage`，为"错误分级呈现"打好了地基（只差 UI 层没用起来）。
3. **安全默认值**：源盘只读、大小校验后原子提交、深度校验可选、删除进回收站、断盘时所有危险写操作 `disabled`。这在 UI 上表现为"按钮变灰"，是正确的产品语言。
4. **微交互的克制**：`patchCardNode` 字段级更新、密度拖动只改 CSS 变量、滚动时降级模糊——说明作者对"闪一下"很敏感，这个品味要保住。
5. **预览器的能力密度**：缩放/平移/沉浸/全屏/实况长按/相邻预取，功能上已经超过多数同类工具，问题只在"表达"。

## 六、一句话建议

如果只能改三件事：**把"备份"从浏览页拿出去、把"反馈"从文档流里拿出来、把"筛选"从互斥改成叠加。** 三件都是结构位移，不动后端，但会让整套界面从"功能都在这儿"变成"知道下一步点哪儿"。
