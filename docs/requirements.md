# Camlib 项目需求

> 版本：v0.1 草案  
> 整理日期：2026-09-05  
> 项目定位：面向个人相机媒体备份与管理的 Windows 桌面应用

## 1. 项目目标

将目前分散的 PowerShell 备份脚本、Python 本地服务、静态网页查看器整合为一个 Tauri 桌面应用，让用户在同一个窗口中完成：

- 相机媒体导入与备份
- 媒体库浏览和预览
- 搜索、筛选和排序
- 收藏、标签及其他管理操作
- 安全删除与备份状态查看

应用不负责替代原始媒体存储设备。原始照片和视频仍由用户指定的媒体库目录保存。

## 2. 已确认的存储策略

项目源码、构建缓存、索引数据库和缩略图缓存放在电脑内置 SSD；原始媒体继续放在外接机械盘或其他用户指定的媒体盘。

默认场景：

```text
SSD
└─ D:\code-collect\camlib       项目源码
   └─ 应用运行数据               索引、缩略图、日志

H 盘
└─ H:\DCIM-local                 原始照片和视频
   └─ YYYY\MM\YYYY-MM-DD\类型\文件
```

要求：

1. 首次启动允许用户选择媒体库根目录。
2. 媒体库路径可在设置中修改。
3. 外接盘未连接时，应用仍可启动，并明确提示媒体库不可用。
4. 不只依赖盘符 `H:`，应记录路径并尽量结合卷标或磁盘唯一标识识别外接盘。
5. 原始媒体默认只读；删除、移动和重命名必须由后端执行并经过安全校验。
6. 索引和缩略图属于可重建数据，损坏后不应影响原始媒体。

## 3. 当前已有数据和原型能力

当前 H 盘原型包含：

- `H:\DCIM-local`：267 个原始文件，约 207 GB
- 176 个 JPG 文件
- 91 个 MP4 文件
- 当前清单识别出 223 个逻辑媒体项
- 支持按年月日和照片/视频分类
- 支持照片与同名视频配对为实况照片
- 支持生成缩略图
- 支持连拍识别
- 支持收藏
- 支持将媒体移入 Windows 回收站
- 支持备份日志和目标盘剩余空间展示

现有原型文件包括：

- `H:\backup_camera.ps1`
- `H:\media-viewer\tools\build_manifest.py`
- `H:\media-viewer\tools\media_server.py`

这些代码和逻辑优先作为迁移参考，而不是立即全部重写。

## 4. 功能需求

### 4.1 媒体库浏览（P0）

- 按年份、月份、日期浏览。
- 查看全部媒体、照片、视频、实况照片。
- 支持缩略图网格和大图/视频预览。
- 支持上一项、下一项、键盘方向键和 Esc 关闭预览。
- 视频使用流式播放，不将整个文件加载到内存。
- 显示文件名、日期、大小、尺寸和视频时长等信息。
- 支持不同缩略图密度。

### 4.2 搜索和筛选（P0）

- 按文件名搜索。
- 按媒体类型筛选。
- 按日期范围或指定日期筛选。
- 按最新、最早和文件名排序。
- 支持筛选连拍媒体。

### 4.3 索引和扫描（P0）

- 启动时检查媒体库是否发生变化。
- 优先进行增量扫描，不重复处理未变化文件。
- 新文件自动加入索引。
- 文件被移除或移动后，索引状态可被识别。
- 扫描、生成缩略图和读取元数据时显示进度。
- 支持取消长时间扫描。

### 4.4 相机备份（P0）

- 自动发现包含 `DCIM` 目录的可移动磁盘。
- 允许用户确认源盘和目标媒体库。
- 预览待导入文件数量、总大小、重复项和冲突项。
- 按拍摄日期整理到：`年\月\日期\媒体类型`。
- 对已有文件进行安全判断，避免重复复制。
- 复制后校验文件大小，失败时记录原因并支持重试。
- 显示复制进度、速度、剩余时间和最终汇总。
- 检查目标盘剩余空间。
- 不修改或删除相机中的文件。
- 备份完成后自动刷新媒体索引。
- `.dng` 和 `.lrv` 是否忽略，应在设置中明确配置；默认延续当前脚本行为。

### 4.5 收藏和标签（P0/P1）

- 收藏状态持久化，不依赖浏览器 `localStorage`。
- 收藏不应因媒体库重新扫描而丢失。
- P1 支持自定义标签、评分和备注。
- P1 支持按收藏、标签和评分筛选。

### 4.6 安全管理（P0）

- 支持选择单个或多个媒体项。
- 实况照片作为一个逻辑项管理，同时处理照片和视频文件。
- 删除默认为移入 Windows 回收站，而不是永久删除。
- 批量删除前显示数量和文件列表摘要。
- 破坏性操作必须二次确认。
- 后端校验所有路径，禁止越过媒体库根目录操作文件。
- 操作失败时保留清晰错误信息和日志。

### 4.7 设置和状态（P1）

- 设置媒体库根目录。
- 设置缩略图缓存位置。
- 设置导入时的文件类型和冲突策略。
- 显示最近一次备份时间、成功数、失败数和剩余空间。
- 显示媒体库连接状态和索引更新时间。
- 提供重新扫描、重建缩略图和重建索引操作。

### 4.8 系统集成（P1）

- 支持 Windows 桌面通知。
- 支持最小化到托盘或后台继续备份。
- 支持从媒体项打开所在文件夹。
- 支持单实例运行，避免多个程序同时修改索引。

## 5. 技术方案

### 5.1 应用框架

- Tauri 2
- 前端：Vanilla TypeScript + HTML/CSS，后续可按需要引入 UI 组件
- 后端：Rust
- 构建工具：Vite
- 数据库：SQLite

### 5.2 前端与后端职责

前端负责界面状态、筛选、网格渲染、预览交互和进度展示；后端负责文件扫描、路径校验、复制、删除、缩略图生成、数据库读写和系统能力调用。

长时间任务不得阻塞界面，应通过 Tauri 事件或 channel 向前端发送进度和状态。

### 5.3 数据模型初稿

核心表可包括：

- `libraries`：媒体库根目录、卷标、状态和最后扫描时间
- `media_items`：逻辑媒体项、类型、拍摄时间、文件大小、哈希、缩略图状态
- `media_files`：逻辑媒体项关联的实际照片/视频文件路径
- `favorites`：收藏状态
- `tags`：标签定义
- `media_tags`：媒体和标签的关联
- `backup_runs`：备份任务及成功/失败统计
- `app_settings`：应用设置

实况照片应以一个 `media_item` 记录表示，并关联照片文件和视频文件，而不是让界面把它们当成两个独立媒体。

### 5.4 缩略图和视频处理

- 缩略图放 SSD 缓存目录。
- 原图和原视频不复制到应用目录。
- 以源文件路径、大小、修改时间和可选哈希判断缩略图是否需要更新。
- 视频缩略图生成可继续使用 ffmpeg；后续需要决定是否作为应用 sidecar 打包。

## 6. 开发阶段

### 阶段 1：桌面化基础

- 将当前网页界面迁移到 Tauri。
- 显示指定媒体库中的照片和视频。
- 实现图片/视频预览。
- 用 Rust command 替代本地 Python HTTP 服务。

### 阶段 2：索引和管理

- 引入 SQLite。
- 实现增量扫描和缩略图缓存。
- 实现收藏、选择、回收站删除。
- 实现媒体库路径设置和断盘提示。

### 阶段 3：备份工作流

- 将 PowerShell 备份能力迁移到 Rust，或先以 sidecar 方式调用。
- 增加导入预览、冲突处理、校验、暂停/继续和失败重试。
- 备份结束后自动扫描并刷新界面。

### 阶段 4：体验增强

- 标签、评分、备注。
- 更完善的 EXIF 元数据读取。
- 托盘、通知、单实例和开机启动选项。
- 重复文件检测和相似媒体整理。

## 7. 第一版验收标准

第一版完成后，用户应能够：

1. 启动 `camlib` 并选择 `H:\DCIM-local` 作为媒体库。
2. 看到按日期组织的媒体缩略图。
3. 点击缩略图查看照片或播放视频。
4. 搜索文件名并按类型、日期筛选。
5. 收藏媒体，关闭应用后再次打开收藏仍然存在。
6. 从相机可移动盘导入新媒体并看到实时进度。
7. 断开 H 盘后应用不会崩溃，并能提示媒体库不可用。
8. 删除媒体时只进入 Windows 回收站，且不会删除媒体库之外的文件。
9. 重启应用后索引、缩略图和用户操作状态保持正常。

## 8. 暂不纳入第一版

- 云同步。
- 多设备同步。
- 在线分享。
- RAW 预览和编辑。
- 图片编辑、视频剪辑。
- 人脸识别和 AI 自动分类。
- 移动端版本。
