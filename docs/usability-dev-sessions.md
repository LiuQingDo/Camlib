## 1. 原则（持续有效）

唯一目标是「好用」：打开就能找到、看完就能管、导完就能信。不追求功能堆量，不为了架构优雅牺牲手感。

执行约束：

1. **一会话一主题。** 做完、自测、提交后再开下一主题；不要顺手做大范围重构。
2. **真实数据只读。** 真实媒体库目录与相机源盘只允许人工只读检查；自动化测试一律用临时目录。
3. **原始媒体默认只读。** 删除必须进 Windows 回收站；备份不得改相机源盘。
4. **Rust 是文件与索引边界。** 前端不拼物理路径、不持久化业务状态到 `localStorage`。
5. **可重建数据与原始媒体分离。** 索引、缩略图、日志在应用缓存/数据目录；可随时重建。
6. **每个会话结束必须能本地跑起来。** `pnpm build` + `cargo test`（以及会话声明的手动检查）通过后再收工。

## 4. 明确延后（第二轮）

以下对好用有帮助，但未纳入第一轮；需要时单开会话，不要塞进样式打磨计划：

- 重复文件/相似媒体整理
- 更完整 EXIF（镜头、ISO、GPS 地图）
- 智能时间线（按事件聚类）
- 多媒体库并行浏览（当前单库为主）
- 自动更新、崩溃上报
- 性能专项（>5 万项库的虚拟滚动、索引分片）
- E2E UI 测试框架

若在使用中发现「每天都会痛」的点，应插入当前迭代之后，而不是无限等待第二轮。

## 5. 会话执行模板（复用）

每个会话开工时：

1. `git status` 保持干净或先处理未提交改动。
2. 读本原则 + 相关源文件与合约文档，列出具体改动清单。
3. 实现 → 单测 → `pnpm build` → `cargo test`。
4. 做「手动好用检查」（该会话验收步骤）。
5. 提交，中文提交信息简述「为什么」。
