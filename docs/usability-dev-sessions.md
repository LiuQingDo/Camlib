# Camlib 好用优先开发会话

> 文档版本：v1.0  
> 整理日期：2026-09-12  
> 前提文档：`docs/requirements.md`、`docs/architecture.md`、`docs/development-notes.md`  
> 本文取代已过期的 `docs/codex-development-workflow.md` 中的会话规划部分。旧文仍可作历史参考，不再作为执行依据。

## 1. 原则

唯一目标是「好用」：打开就能找到、看完就能管、导完就能信。不追求功能堆量，不为了架构优雅牺牲手感。

执行约束：

1. **一会话一主题。** 做完、自测、提交后再开下一主题；不要顺手做大范围重构。
2. **真实数据只读。** `H:\DCIM-local` 与相机源盘只允许人工只读检查；自动化测试一律用临时目录。
3. **原始媒体默认只读。** 删除必须进 Windows 回收站；备份不得改相机源盘。
4. **Rust 是文件与索引边界。** 前端不拼物理路径、不持久化业务状态到 `localStorage`。
5. **可重建数据与原始媒体分离。** 索引、缩略图、日志在应用缓存/数据目录；可随时重建。
6. **每个会话结束必须能本地跑起来。** `pnpm build` + `cargo test`（以及会话声明的手动检查）通过后再收工。

当前代码真实状态（2026-09-12，S9 后）：

- 已实现：媒体库注册/断盘状态、SQLite 索引、增量扫描、实况配对、连拍标记入库、分页查询、日期侧栏、类型/收藏/文件名/标签/评分筛选、缩略图缓存、`camlib://` 受控资源与视频 Range、收藏、多选、回收站删除预览与执行、相机发现/备份预览/执行/重试/取消、设置页、标签与评分、单实例/托盘/通知、真实 CSP、capabilities 最小化、结构化错误码、路径安全回归测试、README 与发布检查清单。
- 已有单元测试：`scanner` / `db` / `backup` / `media` / `infrastructure` / `deletion` / `errors`。
- 后续可做：自动更新、崩溃上报、更多 EXIF、重复检测细化、E2E UI 测试。

## S1 — 浏览底座

### 目标

启动后立刻能看图，列表不再为收藏发几十次 IPC，密度/排序重开还在，媒体库用系统文件夹选择器接入，启动时自动感知库变化。

### 范围

1. **列表收藏化**
   - `query_media` 用 `LEFT JOIN favorites`（或 `EXISTS` 投影）让每条 `MediaItem` 带 `favorite: bool`。
   - 同步改 `MediaItem` / 前端 `MediaItemDto`，删除 `refreshMedia` / `loadMore` 里对 `getMediaItem` 的 N+1。
2. **UI 偏好持久化**
   - 存 `app_settings`（或现有 settings JSON）：`density`、`sort`、`kind`、`favoriteOnly` 不强制全存，至少 `density` 与 `sort`。
   - 重开应用恢复；不要写 `localStorage`。
3. **启动自动轻扫**
   - 库可用时自动触发增量扫描（可用设置关闭，默认开）。
   - 进度沿用现有 `scan-progress` 事件与横幅；不要阻塞首屏浏览已有索引。
4. **原生目录选择**
   - 引入 `tauri-plugin-dialog`（或等价能力），媒体库接入/更换改为「选择文件夹」为主，手输为高级选项。
   - capabilities 与 CSP 同步收紧到刚好够用。
5. **搜索小手感**
   - Enter 提交；清空后自动恢复全库；搜索中显示进行状态。

### 不做

- 标签 UI、托盘、备份重构、错误码体系、全量设置页。

### 验收

- 冷启动打开已有索引的库，网格可滚动，无「每卡片一次 getMediaItem」。
- 改密度/排序后重启仍在。
- 库目录变更时（可用临时目录加删文件）启动能自动扫出变化或给出提示。
- 能通过系统对话框选择文件夹完成注册。
- `pnpm build`、`cargo test` 通过。

### 提示词

```text

先阅读：README 模板可忽略；重点读 docs/requirements.md、docs/architecture.md、docs/development-notes.md、
src/main.ts、src/api/media.ts、src-tauri/src/lib.rs、src-tauri/src/db/mod.rs、src-tauri/src/infrastructure.rs。

本会话主题【S1 浏览底座】，只做下面 5 件事，不要顺手重构无关模块：

1) 列表查询带出 favorite
   - 修改 Repository::query_media，让每条 MediaItem 都包含 favorite 字段（SQL JOIN/EXISTS 投影）。
   - 同步 Rust DTO 与前端 MediaItemDto。
   - 删除 src/main.ts 中 refreshMedia/loadMore 对每个 item 再调 getMediaItem 的 N+1 逻辑。

2) UI 偏好持久化
   - 至少持久化 density 与 sort（存 settings/app_settings，禁止 localStorage）。
   - 启动 bootstrap 时恢复。

   - 库 available 时自动发起增量扫描；设置里可关（默认开）。
   - 不阻塞首屏已有索引；进度事件与现有扫描横幅共用。

4) 原生文件夹选择
   - 增加 tauri-plugin-dialog，注册/更换媒体库以选择文件夹为主。
   - 更新 capabilities；仅申请必要权限。

5) 搜索手感
   - Enter 提交搜索；清空并提交后回到全库。

约束：
- H:\DCIM-local 只读，测试用 tempfile/临时目录。
- 不删除/移动/重命名原始媒体。
- 前端不拼物理路径。
- 完成后运行：pnpm build 与 cargo test（在 src-tauri 下），必须通过。
- 提交信息用中文简述改动。

完成后用 5-10 行总结：改了哪些文件、验收点、已知残留问题。
```

## S2 — 筛选与导航

### 目标

用户能按「连拍」「日期区间」快速收窄结果，并能从卡片直接打开系统资源管理器定位文件。

### 范围

1. **连拍筛选**
   - 查询参数增加 `burstOnly`（或 `burst_group IS NOT NULL`）。
   - 工具栏增加「连拍」筛选 chip；与类型筛选的互斥/组合规则与现有「收藏」保持一致、可预期。
2. **日期区间筛选**
   - 查询支持 `dateFrom` / `dateTo`（YYYY-MM-DD）。
   - UI：侧栏点日期仍可用；增加简易区间选择（两个日期输入或预设：本月/今年/最近30天）。
   - 与现有 `datePrefix` 的优先级写清楚：有区间时忽略 prefix，或合并为一种模型。
3. **打开所在文件夹**
   - 新增 command `media_open_folder`：按 `mediaItemId` 后端解析文件并打开所在目录（Windows Explorer / select 参数更好）。
   - 卡片右键菜单或预览页按钮「打开文件夹」。
   - 禁止接受前端任意路径。
4. **侧栏手感**
   - 年/月默认折叠策略清晰（例如默认展开当前选中年，其余折叠）。
   - 选中日期后标题区与筛选 chip 同步，可一键回到「全部媒体」。
5. **结果稳定**
   - 切换筛选时保持合理滚动位置或回到顶部，避免「跳到中间」的眩晕感。
   - 「加载更多」与筛选条件一致。

### 不做

- 复杂日历组件、地图、人脸/地点。

### 验收

- 只看连拍：结果均有 burst_group。
- 选择日期区间后总数与侧栏高亮一致。
- 点「打开文件夹」弹出资源管理器并定位到对应文件（若文件缺失给出明确错误）。
- 手动：连续切换筛选/日期/排序 10 次无残留错误态。

### 提示词

```text
你在 D:\code-collect\camlib 工作。本会话主题【S2 筛选与导航】。
先读 S1 之后的代码：db query_media、media_query command、src/main.ts 工具栏与侧栏、scanner 里 burst 标记逻辑。

只做：
1) 连拍筛选（后端查询参数 + 前端 chip）
2) 日期区间筛选（dateFrom/dateTo，与 datePrefix 语义写清并测试）
3) media_open_folder：仅接受 mediaItemId，后端解析后打开所在文件夹；卡片/预览提供入口
4) 侧栏年月折叠策略与「全部媒体」一键返回
5) 切换筛选时的滚动/加载更多行为整理，避免错位

约束与验收同项目原则：临时目录测试、原始媒体只读、pnpm build + cargo test 通过。
不要做标签 UI、托盘、备份重构。
完成后总结：参数变更、UI 变更、手动检查步骤。
```

## S3 — 预览沉浸

### 目标

预览像相册应用：切换快、信息全、键盘顺、失败可恢复。

### 范围

1. **相邻预取**
   - 打开当前项时预取前后 1–2 项的预览资源（控制并发，沿用现有缩略图队列思想）。
2. **元数据面板**
   - 预览页显示：文件名、拍摄日期、类型、尺寸、时长、总大小、库内相对路径、收藏状态。
   - 用已有 `media_get` / preview DTO，不够再补 command；不要暴露无必要绝对路径。
3. **实况照片**
   - 明确区分「静态图 / 视频轨」；支持一键只看图或只播视频；自动循环可关。
4. **视频体验**
   - 加载失败有原因与重试；缓冲中不白屏。
   - 快捷键：空格播放/暂停、←→ 切换、Esc 关闭、F 全屏（或双击）。
5. **缩略图失败态**
   - 「预览不可用」可点重试；不把失败缓存成永久失败（或提供重建入口提示）。
6. **性能底线**
   - 大页 120 项滚动时不重复 IPC；关闭预览后不泄漏 object URL / 重复 decode。

### 不做

- 编辑、裁剪、RAW 解码、滤镜。

### 验收

- 打开照片后连按 → 切换流畅，前后已预取项无长时间白块。
- 预览页能读到尺寸/时长/大小等信息。
- 视频失败可重试；键盘快捷键全部生效。
- 实况照片不会把用户搞糊涂（图和视频角色清晰）。

### 提示词

```text
你在 D:\code-collect\camlib 工作。本会话主题【S3 预览沉浸】。
先读 media.rs 的 preview/thumbnail/stream、src/main.ts 的 loadModalAsset 与预览 DOM。

只做预览体验，不改备份、不改扫描算法：
1) 前后项预取（有限并发）
2) 预览元数据面板（来自后端 DTO）
3) 实况照片交互澄清
4) 视频错误/缓冲/全屏与快捷键
5) 缩略图失败重试

约束：视频继续走受控协议与 Range，不把大文件读进 IPC；测试用临时媒体。
pnpm build + cargo test 通过。
总结时列出新增快捷键表。
```

## S4 — 管理手感

### 目标

删除与批量操作「看得见、点得准、后悔药清楚」。

### 范围

1. **确认对话框**
   - 用系统对话框或应用内高保真确认层替换 `window.confirm`。
   - 文案包含：媒体项数、文件数、总大小、前若干文件名、明确写「移入回收站，可恢复」。
2. **删除过程反馈**
   - 执行中有进度（至少阶段与已处理文件数）。
   - 部分失败：保留成功数、失败文件列表与原因；不把整批标成成功。
   - 成功后 toast/横幅 + 网格立即移除，无需整页闪烁。
3. **选择手感**
   - 支持 Shift 范围选择（基于当前排序结果）。
   - 全选当前结果已有，保留；补充「反选」可选。
4. **收藏批量**
   - 选中多项后可批量收藏/取消收藏（后端按事务写）。
5. **安全文案**
   - 危险按钮样式与二次确认一致；路径越界等后端拒绝时显示可理解信息。

### 不做

- 回收站浏览器、跨库移动、云回收站。

### 验收

- 删除确认不再是浏览器默认 confirm。
- 人为制造 1 个失败文件（临时目录只读或占用）时，结果准确且可继续。
- Shift 范围选择正确。
- 批量收藏后刷新仍在。

### 提示词

```text
你在 D:\code-collect\camlib 工作。本会话主题【S4 管理手感】。
先读 deletion.rs、media_delete_* commands、src/main.ts 的 selection/deleteSelected。

只做：
1) 替换 window.confirm 为应用内确认或系统 dialog（说明回收站语义）
2) 删除进度与部分失败明细展示
3) 删除成功后的即时网格反馈
4) Shift 范围多选
5) 批量收藏/取消收藏

约束：删除仍必须进 Windows 回收站；后端只接受 media_item_ids；禁止前端传任意路径。
临时目录 + Fake/真实回收站二选一，但不要碰 H:\DCIM-local。
pnpm build + cargo test 通过。
```

## S5 — 备份闭环

### 目标

相机插上 → 选盘 → 看懂预览 → 复制 → 知道结果 → 索引里立刻看到新片。

### 范围

1. **三步流**
   - 面板重排为清晰步骤：选择源/目标 → 预览摘要 → 执行进度。
   - 摘要突出：将复制 N 个文件、跳过 M、冲突 K、所需空间、目标剩余空间。
2. **空间与冲突前置**
   - 空间不足直接禁用开始并解释；冲突策略影响预览数字与文案一致。
3. **执行与取消**
   - 进度条按字节；显示速度与剩余时间（可估）。
   - 取消在安全点停止，文案说明已完成部分保留。
4. **完成引导**
   - 成功后自动触发扫描，提示「新增 X / 跳过 Y / 失败 Z」。
   - 提供「查看新导入」：跳转到对应日期或最近导入筛选（可按 first_seen_at 排序）。
5. **失败重试**
   - 保留/强化 `backup_retry_failed` UI：只重试失败项。
6. **备份历史**
   - 最近 N 次备份列表（时间、源、成功/失败/跳过、大小）；点开可见失败明细。

### 不做

- 多目标同步、增量镜像策略配置、云备份。

### 验收

- 用临时「相机盘」（目录含 DCIM 结构）走完整流程。
- 人为制造空间不足/冲突时预览与执行一致。
- 完成后索引可见新文件，且能一键定位。
- 失败可重试且不重复复制已成功文件（按现有冲突策略）。

### 提示词

```text
你在 D:\code-collect\camlib 工作。本会话主题【S5 备份闭环】。
先读 backup.rs、backup_* commands、src/main.ts 备份面板与 onBackupProgress。

只做备份体验闭环：
1) 三步式备份面板与摘要数字
2) 空间不足/冲突前置提示
3) 进度（字节、速度、ETA）与取消安全点文案
4) 完成后自动扫描 + 新导入引导（可按首次入库时间）
5) 失败重试 UI
6) 最近备份历史（读 backup_runs / backup_items）

约束：源盘只读；复制仍是临时文件+校验+提交（保持现有安全策略）；测试用临时源/目标目录。
pnpm build + cargo test 通过。
```

## S6 — 设置与库状态

### 目标

用户能理解应用存在哪些数据、如何重建、如何换库，而不是只能「碰运气点扫描」。

### 范围

1. **设置抽屉/页面**
   - 入口在侧栏或顶栏；分区：媒体库、扫描与索引、缩略图缓存、备份默认项、关于。
2. **媒体库区**
   - 显示根路径、卷标、盘符、状态、最后扫描时间、媒体数。
   - 更换库、重新扫描、打开数据目录（应用数据/缓存）。
3. **扫描与索引**
   - 显示最近 scan_runs 摘要。
   - 增量扫描 / 全量重建索引（确认后执行）；重建期间可取消。
4. **缩略图**
   - 缓存目录可改；显示缓存路径与大致体积（可选）。
   - 「重建缩略图」入口（已有 command，补 UI）。
5. **备份默认项**
   - 默认忽略扩展名、默认冲突策略；与备份面板共享，避免两处真相。
6. **关于**
   - 版本、数据目录说明、ffmpeg 是否可用（检测结果）。

### 不做

- 账号、云、多语言完整 i18n 框架。

### 验收

- 仅通过设置页即可完成：看状态、改缩略图目录、重建缩略图、全量重扫、改备份默认项。
- 破坏性操作（全量重建）有确认。
- ffmpeg 缺失时「关于」或备份相关处有可理解提示。

### 提示词

```text
你在 D:\code-collect\camlib 工作。本会话主题【S6 设置与库状态】。
先读 infrastructure settings、get_app_settings/set_* commands、thumbnail_rebuild_start、scan_runs 表。

只做设置与状态可视化，不要重写扫描/备份核心：
1) 设置面板（分区 UI）
2) 媒体库状态卡 + 更换/重扫/打开数据目录
3) 索引摘要 + 全量重建（确认/取消）
```

## S7 — 标签与评分

### 目标

用标签和星级把「好看的」「要修的」「要分享的」固定下来，而不是只靠收藏一个维度。

### 范围

1. **标签 CRUD**
   - 创建/重命名/删除标签（删除标签不删媒体）。
2. **打标签**
   - 卡片多选批量打标；预览页添加/移除标签。
3. **筛选**
   - 按标签筛选；与类型/收藏/日期可组合。
4. **评分**
   - 1–5 星，预览页可改；列表卡片可选显示角标。

5. **备注（可选，若时间够）**

- 按标签筛选结果正确。
- 评分可改可筛。

## S8 — 系统融入

### 目标

长任务在后台不丢，多开不脏库，完成有系统级提醒。

### 范围

1. **单实例**
   - 第二次启动聚焦已有窗口而不是再开一个写库实例。
2. **托盘（可选默认开）**
   - 最小化到托盘；托盘菜单：打开、扫描、最近备份状态、退出。
   - 关闭按钮行为可设置：退出 / 最小化到托盘。
3. **系统通知**
   - 扫描完成/失败、备份完成/失败、断盘提醒（可设置开关，默认重要事件开）。
4. **长任务可恢复查看**
   - 设计稿中的 `job_get` 可降级为：应用重启后从 `scan_runs`/`backup_runs` 显示最近结果，而不是假装任务还在跑。
5. **断盘体验**
   - 媒体库不可用时：横幅清晰、禁用危险操作、恢复后一键重扫。

### 不做

- 开机自启可作为开关但默认关；多用户服务、远程访问。

### 验收

- 双开第二次激活原窗口。
- 备份完成能收到系统通知（Windows）。
- 备份中途杀掉应用，重启后历史里能看到未完成/失败状态并可重试。

### 提示词

```text
你在 D:\code-collect\camlib 工作。本会话主题【S8 系统融入】。
先读 tauri.conf.json、capabilities、ScanManagerState/BackupManagerState、scan_runs/backup_runs。

只做：
1) 单实例
2) 托盘 + 关闭行为设置
3) 系统通知（扫描/备份/断盘，可开关）
4) 重启后从 runs 表展示最近任务结果（不做复杂 job 恢复机）
5) 断盘时危险操作禁用与恢复引导

约束：通知与托盘失败不能影响主窗口启动；权限最小化。
pnpm build + cargo test 通过；在 Windows 上手动验证单实例与通知。
```
