# Camlib Codex 分步骤开发流程

> 基于 `docs/requirements.md`、当前仓库结构和 H 盘现有原型整理。
>
> 文档版本：v0.1  
> 整理日期：2026-09-05

## 1. 使用范围

本文档用于指导 Camlib 在 Codex 中按“分步骤、分会话”的方式开发。每个会话只处理一个边界清晰的目标，完成并验证后再开始下一个会话。

开发过程中必须把 H 盘视为真实用户数据盘：

- `H:\DCIM-local` 只允许只读检查。
- 不得在开发测试中批量复制、移动、重命名或删除 H 盘媒体。
- 删除功能只能使用临时测试目录验证。
- 备份功能只能使用临时源盘和临时目标盘模拟验证。
- 不得把 H 盘中的静态清单、缩略图或原始媒体复制进项目仓库。

## 2. 当前实际状态

### 2.1 项目仓库

当前仓库 `D:\code-collect\camlib` 还是 Tauri 官方最小模板：

```text
camlib
├─ docs
│  └─ requirements.md
├─ src
│  ├─ main.ts
│  └─ styles.css
├─ src-tauri
│  ├─ src/lib.rs
│  ├─ src/main.rs
│  ├─ tauri.conf.json
│  └─ capabilities/default.json
├─ package.json
├─ pnpm-lock.yaml
├─ pnpm-workspace.yaml
├─ tsconfig.json
└─ vite.config.ts
```

目前：

- 前端仍是默认示例页面。
- Rust 后端只有 `greet` command。
- 尚未引入 SQLite、媒体扫描、缩略图、备份或安全删除功能。
- 当前 Git 仓库还没有提交记录。

### 2.2 H 盘原型

```text
H:\
├─ DCIM-local
│  └─ 2026\08 或 09\YYYY-MM-DD\照片或视频\文件
├─ media-viewer
│  ├─ assets
│  │  ├─ app.js
│  │  ├─ data.js
│  │  ├─ management.js
│  │  ├─ style.css
│  │  ├─ manifests
│  │  └─ thumbs
│  └─ tools
│     ├─ build_manifest.py
│     └─ media_server.py
├─ backup_camera.ps1
├─ backup_log.txt
└─ index.html
```

实际数据盘点：

- 267 个物理媒体文件。
- 176 个 JPG、91 个 MP4。
- 总大小约 222.47 GB，即 Windows 统计约 207.20 GiB。
- 原型清单识别出 223 个逻辑媒体项：135 个照片、48 个视频、40 个实况照片。

现有原型可作为迁移参考，已经包含日期分类、实况照片配对、缩略图、连拍识别、收藏、回收站删除、备份日志和剩余空间展示等逻辑。

需要注意：原型清单最后生成于 2026-09-04，而备份日志已有 2026-09-05 记录；原型不是可靠的正式索引层。正式版应以 SQLite 和增量扫描为准。

## 3. 总体开发顺序

```text
架构基线
  ↓
设置与路径识别
  ↓
SQLite 数据层
  ↓
增量扫描与索引
  ↓
媒体库前端
  ↓
缩略图与预览
  ↓
收藏与安全删除
  ↓
备份发现与预览
  ↓
备份执行与重试
  ↓
验收、打包与发布加固
```

不要在扫描、删除和备份尚未稳定前，把真实 H 盘接入自动化测试。

## 5. 分会话开发计划与专用提示词

### 会话 0：建立基线与技术设计

目标：完成架构审计、数据模型、command/event 设计和测试策略，不实现业务功能。

建议产出：

- `docs/architecture.md`
- `docs/data-model.md`
- `docs/development-notes.md`

专用提示词：

```text
本会话只做架构审计，不实现业务功能。

请完整检查当前仓库，以及以下 H 盘原型文件：
- H:\backup_camera.ps1
- H:\media-viewer\tools\build_manifest.py
- H:\media-viewer\tools\media_server.py
- H:\media-viewer\assets\app.js
- H:\media-viewer\assets\management.js

请整理并写入：
- 当前代码现状
- 目标架构
- SQLite 表结构
- 前后端 command API
- 长任务进度 event/channel 设计
- 路径安全策略
- 测试策略
- 分阶段开发顺序

不要复制 H 盘媒体、缩略图或静态清单到仓库。完成后运行 pnpm build 和 cargo check。
```

### 会话 1：Tauri 基础设施和应用设置

目标：实现应用数据目录、缓存目录、媒体库路径选择、卷标/卷标识记录和断盘状态。

要求：

- 不把 `H:` 写死在业务逻辑中。
- 所有路径都必须规范化。
- 覆盖媒体库不存在、外接盘未连接和路径切换场景。

专用提示词：

```text
实现 Camlib 的基础设施层，本会话只包括：
- 应用设置存储
- 媒体库根目录选择
- 缩略图缓存目录
- 盘符、卷标和卷唯一标识记录
- 媒体库可用/断开状态
- 前端调用这些能力所需的最小 Tauri command

暂不实现媒体扫描、备份、删除和复杂界面。所有路径必须经过规范化。为路径校验和断盘场景添加测试，使用临时目录，不接触 H:\DCIM-local。
```

### 会话 2：SQLite 数据层

目标：引入 SQLite、迁移机制、Repository 和类型安全 DTO。

核心表：

```text
libraries
media_items
media_files
favorites
tags
media_tags
backup_runs
app_settings
```

关键约束：

- 数据库放在 SSD 的应用数据目录。
- 文件保存相对媒体库根目录的路径。
- 实况照片是一个 `media_item`，关联照片和视频两个 `media_files`。
- 收藏不能依赖 `localStorage`。

专用提示词：

```text
实现 Camlib 的 SQLite 数据层。

请建立可重复执行的 migration，创建 libraries、media_items、media_files、favorites、tags、media_tags、backup_runs、app_settings，并建立必要索引。

实现类型安全的 Rust Repository 和前端 DTO。实况照片必须是一个逻辑媒体项并关联照片和视频文件。数据库放在应用数据目录，原始文件只保存相对媒体库根目录的路径。

本会话不实现文件扫描、缩略图和删除。使用临时目录或内存数据库测试，不接触 H:\DCIM-local。完成后运行 cargo fmt、cargo check 和测试。
```

### 会话 3：增量扫描和媒体索引

目标：扫描媒体库，识别新增、变更、移除文件，建立逻辑媒体项，并提供进度和取消能力。

专用提示词：

```text
实现 Camlib 的媒体扫描和增量索引服务。

要求：
- 扫描路径来自数据库配置，不允许写死 H:
- 只处理允许的媒体类型
- 使用相对路径保存文件
- 根据路径、大小、修改时间判断是否需要重新处理
- 识别新增、修改、移除和失效文件
- 同日期、同 stem 的照片和视频合并为 live media_item
- 扫描不能阻塞 UI
- 通过 Tauri event 或 channel 报告阶段、当前文件、已处理数、总数和错误
- 支持取消扫描
- 扫描失败不能破坏已有索引

使用临时目录构造照片、视频、实况照片、重复文件和失效文件。不要扫描或修改真实 H:\DCIM-local。
```

### 会话 4：媒体库前端界面

目标：替换默认页面，实现日期导航、媒体网格、搜索、筛选、排序和密度调整。

专用提示词：

```text
实现 Camlib 第一版媒体库前端。

可以参考 H:\media-viewer 的交互，但不得直接依赖静态 Manifest、localStorage 或固定 H: 路径。

实现：
- 年/月/日期导航
- 媒体网格和日期分组
- 照片、视频、实况照片分类
- 文件名搜索
- 日期筛选
- 最新、最早、文件名排序
- 缩略图密度调整
- 空状态、加载状态、扫描进度和媒体库断开提示

所有数据通过 Tauri command 获取，保持前后端类型一致。暂不实现删除、备份和标签。完成后运行 pnpm build，并检查键盘操作和窗口尺寸适配。
```

### 会话 5：缩略图和媒体预览

目标：在 SSD 缓存缩略图，完成图片、视频和实况照片预览。

专用提示词：

```text
实现 Camlib 的缩略图和媒体预览能力。

要求：
- 缩略图只写入 SSD 缓存目录，不复制原媒体
- 缓存键至少包含相对路径、大小和修改时间
- 图片缩略图正确处理 EXIF 方向
- 视频使用流式播放，不把整个文件读入内存
- 支持照片、视频和实况照片预览
- 支持上一项、下一项、方向键和 Esc
- 缩略图生成和视频首帧处理支持进度、错误和取消
- 明确 ffmpeg 在开发和打包环境中的来源

使用小型临时媒体 fixture 测试。禁止对 H:\DCIM-local 批量生成或重建缩略图。
```

### 会话 6：收藏、选择和安全删除

目标：实现 SQLite 收藏、多选、实况照片整体操作、回收站删除和路径越界防护。

专用提示词：

```text
实现 Camlib 的收藏和安全管理功能。

要求：
- 收藏保存到 SQLite，重启和重新扫描后仍保留
- 支持单选、多选和当前结果全选
- 删除前显示媒体数量和文件摘要
- 实况照片删除时同时处理照片和视频
- 删除默认进入 Windows 回收站，不允许永久删除
- 后端对所有路径执行 canonicalize 和媒体库根目录 containment 校验
- 禁止通过 ..、符号链接或伪造相对路径越过媒体库根目录
- 删除失败时保留明确错误和日志
- 删除完成后刷新索引和缩略图状态

测试必须覆盖路径穿越、媒体库外文件、实况照片、部分失败和重复删除。只使用临时测试目录，严禁对 H:\DCIM-local 做删除测试。
```

### 会话 7：备份发现和导入预览

目标：迁移 `backup_camera.ps1` 的核心行为，实现相机发现、导入预览、重复判断、冲突识别和空间检查。

专用提示词：

```text
实现 Camlib 的相机发现和备份预览功能。

以 H:\backup_camera.ps1 为行为参考，但不要直接执行 PowerShell 脚本。

要求：
- 自动发现包含 DCIM 目录的可移动磁盘
- 允许用户选择源盘和目标媒体库
- 优先从文件名解析拍摄日期，失败时使用文件时间
- 按 年\月\日期\照片或视频 生成目标路径
- .dng 和 .lrv 使用配置化忽略策略，默认保持现有脚本行为
- 预览素材数量、总大小、已存在文件、冲突文件和忽略文件
- 检查目标盘剩余空间
- 不修改相机源盘
- 记录 backup_runs，但本会话不真正复制文件

使用临时目录模拟相机盘，覆盖重复文件、同名不同内容、缺失日期和空间不足场景。不要使用真实 H 盘作为测试目标。
```

### 会话 8：备份执行、校验和重试

目标：实现确认后的复制、进度、速度、剩余时间、取消、失败重试和扫描刷新。

实现 Camlib 的备份执行流程。

要求：

- 源文件只读，不得删除或移动相机中的文件
- 支持文件级和字节级进度
- 显示速度、预计剩余时间和当前文件
- 支持取消，取消后保留已成功文件和任务状态
- 复制后校验文件大小，失败文件可重试
- 冲突策略来自设置
- 备份任务持久化到 backup_runs
- 完成后自动触发增量扫描
- 异常时保留可读错误和日志

先使用临时源盘和临时目标盘做集成测试。除非用户明确授权，不得把真实 H:\DCIM-local 作为目标，也不得执行真实批量导入。

## 7. 阶段验收门槛

### 门槛 A：基础可运行

- `pnpm build` 通过。
- `cargo check` 通过。
- 应用可以启动和关闭。
- 媒体库路径可以设置并持久化。

### 门槛 B：索引可恢复

- 首次扫描可以建立索引。
- 增量扫描不会重复处理未变化文件。
- 文件移除后能标记失效。
- 扫描取消后数据库仍可用。

### 门槛 C：浏览可用

- H 盘断开时应用不崩溃。
- 图片和视频可以预览。
- 搜索、筛选、排序和收藏正常。
- 收藏不依赖浏览器 `localStorage`。

### 门槛 D：破坏性操作安全

- 删除前二次确认。
- 实况照片整体处理。
- 只能进入回收站。
- 任何媒体库外路径都被拒绝。

### 门槛 E：备份可控

- 能发现包含 DCIM 的可移动盘。
- 能预览重复项、冲突项和空间需求。
- 复制后有校验。
- 失败可重试，完成后自动刷新索引。

以下功能放在第一版稳定后：

- 标签、评分和备注。
- 更完整的 EXIF 元数据。
- Windows 通知。
- 系统托盘和后台备份。
- 单实例运行。
- 开机启动。
- 重复文件和相似媒体整理。
- 云同步、移动端、在线分享、RAW 编辑和 AI 分类。
