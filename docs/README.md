## 3. 维护约定

1. **一份文档只有一个职责。** 需求不写实现，架构不写待办，诊断不写方案。
2. **待办类文档必须能勾。** `ui-ux/README.md` 的进度表是唯一进度真相；其他地方的"TODO"要在那里有对应行。
3. **历史计划不删，移入 `archive/`。** 它们的价值是"当时为什么这么决定"，不是"接下来做什么"。
4. **数字要能被命令复现。** 文中出现"472 条覆盖规则""58 处 backdrop-filter"这类计数时，附上复现命令（`grep -c`），否则下次没人知道怎么核对。
5. **文档漂移算 bug。** 发现文档与代码不一致，要么改文档，要么在 `ui-ux/README.md` 记一条待办——不要放着。
